Техническая документация репозитория **Zedra | Трекер проектов** — описание кодовой базы, программных интерфейсов composables, контрактов компонентов, правил валидации и сборки.


## 1. Общие сведения

Приложение — одностраничное клиентское SPA на Nuxt 4 без серверной части. Вся логика выполняется в браузере, состояние хранится в реактивных переменных Vue и сериализуется в `localStorage`.

| Параметр | Значение |
| --- | --- |
| Имя пакета | `app` (`package.json`) |
| Тип модулей | ESM (`"type": "module"`) |
| Фреймворк | Nuxt `^4.5.2`, Vue `^3.5.42` |
| Рендеринг | `ssr: false` — только клиентский |
| Язык | TypeScript 5 |
| Менеджер пакетов | Bun (`bun.lock`) |
| Preset Nitro | `bun` |
| UI | shadcn-vue (reka-ui) + Tailwind CSS 4 |
| Иконки | `@lucide/vue` |
| Уведомления | `vue-sonner` |
| Тесты | не настроены (нет тестового фреймворка и скрипта `test`) |

### 1.1. Команды

```bash
bun install        # установка зависимостей (postinstall → nuxt prepare)
bun run dev        # сервер разработки
bun run build      # сборка приложения
bun run preview    # предпросмотр сборки
bun run generate   # статическая генерация → .output/public
```

Отдельного скрипта проверки типов в `package.json` нет; `vue-tsc` установлен как devDependency и вызывается вручную:

```bash
bunx vue-tsc --noEmit
```

## 4. Модель данных

Определения — `app/types/index.ts`.

```ts
type Priority = 'low' | 'medium' | 'high'

interface Column {
  id: string        // идентификатор колонки; используется как Task.status
  title: string
}

interface Project {
  id: string
  name: string
  description: string
  archived: boolean
  columns: Column[]
  createdAt: string // ISO 8601
}

interface Task {
  id: string
  projectId: string // связь с Project.id
  title: string
  description: string
  priority: Priority
  deadline: string  // 'YYYY-MM-DD' из <input type="date"> либо '' — срок не задан
  assignee: string
  status: string    // Column.id внутри проекта
  order: number     // позиция в колонке при сортировке «по порядку добавления»
  createdAt: string // ISO 8601
}

interface TrackerState {
  projects: Project[]
  tasks: Task[]
}
```

Особенности модели:

- **Связи по идентификаторам, без вложенности.** Задачи лежат в плоском массиве и связаны с проектом через `projectId`, с колонкой — через `status`. Колонки, напротив, вложены в проект (`Project.columns`).
- **Идентификаторы генерируются на клиенте** функцией `createId()`: `Math.random().toString(36).slice(2, 10) + Date.now().toString(36)`. Функция не экспортируется.
- **Колонки по умолчанию** (`defaultColumns()`, экспортируется) имеют фиксированные идентификаторы `todo`, `in-progress`, `done` и заголовки «К выполнению», «В работе», «Выполнено». Колонки, созданные пользователем, получают идентификатор из `createId()`.
- **Пустая строка — способ обозначить отсутствие значения** для `description`, `deadline` и `assignee`; `null`/`undefined` в модели не используются.

## 5. Composable `useTracker`

Файл `app/composables/useTracker.ts`. Единственный источник истины для данных приложения. Константа хранилища — `STORAGE_KEY = 'tracker-data'`.

### 5.1. Состояние

Состояние создаётся через `useState`, поэтому ключи глобальны и все вызовы `useTracker()` в любом компоненте работают с одними и теми же данными — обёртка вокруг состояния не нужна.

| Ключ `useState` | Тип | Назначение |
| --- | --- | --- |
| `tracker-projects` | `Ref<Project[]>` | список проектов |
| `tracker-tasks` | `Ref<Task[]>` | список задач всех проектов |
| `tracker-loaded` | `Ref<boolean>` | защита от повторного чтения хранилища |

### 5.2. Производные значения

| Имя | Тип | Значение |
| --- | --- | --- |
| `activeProjects` | `ComputedRef<Project[]>` | проекты с `archived === false` |
| `archivedProjects` | `ComputedRef<Project[]>` | проекты с `archived === true` |

Так как composable возвращает объект без деструктуризации, в шаблонах страниц значения читаются как `tracker.activeProjects.value.length` — автораскрытия `.value` для вложенных в объект ref-ов не происходит.

### 5.3. Функции чтения

| Функция | Сигнатура | Поведение |
| --- | --- | --- |
| `getProject` | `(id: string) => Project \| undefined` | поиск проекта по идентификатору |
| `getProjectTasks` | `(projectId: string) => Task[]` | все задачи проекта (новый массив) |
| `countTasks` | `(projectId: string) => number` | число задач проекта |

### 5.4. Функции записи

Каждая операция изменения вызывает `save()` — отдельного сохранения из компонентов не требуется. Все строковые поля проходят `trim()` внутри composable; поле `deadline` записывается без нормализации.

| Функция | Сигнатура | Поведение |
| --- | --- | --- |
| `createProject` | `(name, description) => Project` | создаёт проект с `defaultColumns()`, `archived: false`, `createdAt` = текущий момент; возвращает созданный объект |
| `updateProject` | `(id, name, description) => void` | обновляет название и описание; при отсутствии проекта — тихий выход |
| `deleteProject` | `(id) => void` | удаляет проект **и все его задачи** |
| `setProjectArchived` | `(id, archived: boolean) => void` | переводит проект в архив и обратно; задачи не затрагиваются |
| `addColumn` | `(projectId, title) => void` | добавляет колонку с новым `createId()` в конец списка |
| `renameColumn` | `(projectId, columnId, title) => void` | переименовывает колонку; пустая строка не отклоняется |
| `deleteColumn` | `(projectId, columnId) => void` | **не выполняется, если в проекте одна колонка**; задачи удалённой колонки переносятся в первую колонку списка |
| `createTask` | `(payload) => Task` | `payload`: `projectId`, `title`, `description`, `priority`, `deadline`, `assignee`, `status`. Поле `order` = число задач проекта с тем же `status` на момент создания |
| `updateTask` | `(id, payload) => void` | `payload` тот же без `projectId`; `order` и `createdAt` не меняются |
| `deleteTask` | `(id) => void` | удаляет задачу |
| `moveTask` | `(id, status) => void` | меняет колонку задачи; если `status` совпадает с текущим — выход без изменений и без записи. `order` = число задач в целевой колонке до перемещения |

### 5.5. Работа с `localStorage`

**Чтение — `load()`.** Вызывается один раз из `onMounted` в `app/app.vue`. Флаг `loaded` устанавливается **до** чтения, поэтому повторные вызовы игнорируются даже при ошибке. Массивы `projects` и `tasks` присваиваются только после проверки `Array.isArray`; прочие поля JSON игнорируются. Схема данных не версионируется и не мигрируется.

**Запись — `save()`.** Сериализует `{ projects, tasks }` в ключ `tracker-data`.

**Обработка ошибок.** Обе функции обёрнуты в `try/catch`, исключение поглощается и заменяется уведомлением `toast.error`:

| Ситуация | Сообщение |
| --- | --- |
| Повреждённый JSON при чтении | «Не удалось прочитать данные» / «Локальное хранилище повреждено, приложение запущено с пустым состоянием.» |
| Исчерпана квота при записи | «Не удалось сохранить данные» / «Хранилище браузера переполнено. Удалите часть задач или очистите данные сайта.» |

Приложение в обоих случаях продолжает работу. Следствие, о котором нужно помнить при отладке: после ошибки чтения состояние остаётся пустым, и первая же операция записи перезаписывает повреждённое содержимое ключа.

### 5.6. Ключи браузерного хранилища

| Ключ | Владелец | Содержимое |
| --- | --- | --- |
| `tracker-data` | `useTracker` | `{ "projects": Project[], "tasks": Task[] }` |
| `tracker-theme` | `@nuxtjs/color-mode` | `light` / `dark` |

## 6. Composable `useTaskHelpers`

Файл `app/composables/useTaskHelpers.ts` — чистые функции и справочники без состояния. Все экспорты доступны через автоимпорт, в том числе прямо в шаблонах (`priorityColors[task.priority]`).

| Экспорт | Тип | Значение |
| --- | --- | --- |
| `priorityLabels` | `Record<Priority, string>` | `low` → «Низкий», `medium` → «Средний», `high` → «Высокий» |
| `priorityColors` | `Record<Priority, string>` | CSS-классы индикатора: `bg-sky-500`, `bg-amber-500`, `bg-red-500` |
| `priorityWeight` | `Record<Priority, number>` | `low: 1`, `medium: 2`, `high: 3` — вес для сортировки |
| `formatDate` | `(value: string) => string` | `''` для пустой строки; исходное значение, если дата не разбирается; иначе `toLocaleDateString('ru-RU')` в формате ДД.ММ.ГГГГ |
| `isOverdue` | `(deadline: string) => boolean` | `false` для пустой и некорректной даты; иначе сравнение с сегодняшней датой, у которой время обнулено (`setHours(0,0,0,0)`) |

`isOverdue` не учитывает статус задачи: выполненная задача с прошедшим сроком также считается просроченной (см. [Ограничения](/guide/limitations), п. 13).

## 7. Маршруты и страницы

Маршрутизация файловая (`app/pages/`).

| Маршрут | Файл | Назначение |
| --- | --- | --- |
| `/` | `pages/index.vue` | список проектов |
| `/projects/:id` | `pages/projects/[id].vue` | канбан-доска проекта |
| прочее | `app/error.vue` | экран «404 — Такого пути нет.» |

### 7.1. `pages/index.vue`

Локальное состояние: `dialogOpen`, `editing` (`Project | null` — признак режима редактирования), `confirmOpen`, `deletingId`.

Структура: заголовок с кнопкой «Добавить проект» (`data-testid="add-project"`), `Tabs` с вкладками «Активные»/«Архив» и счётчиками, сетка карточек (`md:grid-cols-2 lg:grid-cols-3`), заглушки для пустых списков.

Карточка активного проекта содержит название, описание (или «Без описания»), бейдж с числом задач, ссылку «Открыть доску» и `DropdownMenu` с пунктами «Редактировать», «Архивировать», «Удалить». Карточка архивного проекта вместо меню предлагает «Восстановить» и кнопку удаления.

Каждая операция сопровождается `toast.success`: «Проект создан», «Проект обновлён», «Проект удалён», «Проект архивирован», «Проект восстановлен из архива».

### 7.2. `pages/projects/[id].vue`

Проект определяется как `computed` от `route.params.id`. Если `getProject` возвращает `undefined`, отображается заглушка «Проект не найден» со ссылкой на список — этот же экран виден при переходе по идентификатору удалённого проекта. Проверки `archived` здесь нет: доска архивного проекта открывается по прямому URL, хотя ссылок на неё в интерфейсе нет.

**Состояние фильтров:** `search`, `priorityFilter` (`all`), `deadlineFilter` (`all`), `sortBy` (`created`). Значения не сохраняются между сессиями; `resetFilters()` возвращает их к значениям по умолчанию.

**Конвейер `filteredTasks`** (`computed`) применяется в указанном порядке:

1. выборка задач проекта — `getProjectTasks`;
2. поиск: подстрока в `title`, регистронезависимо, запрос проходит `trim().toLowerCase()`; описание, исполнитель и другие поля не учитываются;
3. фильтр приоритета: точное совпадение, если значение не `all`;
4. фильтр срока: `overdue` → `isOverdue(deadline)`, `with-deadline` → срок задан, `no-deadline` → срок пуст;
5. сортировка копии массива:

| `sortBy` | Правило |
| --- | --- |
| `created` (по умолчанию) | `a.order - b.order` по возрастанию |
| `priority` | по убыванию `priorityWeight` — сначала высокий |
| `deadline` | по возрастанию строк `YYYY-MM-DD`; задачи без срока уходят в конец |
| `title` | `localeCompare(..., 'ru')` |

Функция `tasksInColumn(columnId)` разбирает результат по колонкам. Счётчик `overdueCount` в заголовке считается по **всем** задачам проекта, независимо от фильтров, тогда как бейдж количества в заголовке колонки показывает число **отфильтрованных** задач.

**Drag-and-drop.** Реализован на нативном HTML5 Drag and Drop API, без библиотек. Колонка (`<section>`) обрабатывает `dragover.prevent` (запись `dragOverColumn` — подсветка рамкой и фоном), `dragleave` (сброс) и `drop.prevent` → `onDrop`, который читает идентификатор задачи из `dataTransfer.getData('text/plain')` и вызывает `moveTask`. Карточка сбрасывает подсветку событием `dragend`.

**Диалог колонок.** Переименование выполняется по событию `update:model-value` поля ввода, то есть `renameColumn` и `save()` вызываются на каждое нажатие клавиши; отдельной кнопки сохранения нет. Добавление колонки проверяет непустое название и выводит ошибку в `columnError`. Попытка удалить последнюю колонку даёт `toast.error('Нельзя удалить последнюю колонку')` — проверка дублируется в странице и в `deleteColumn`.

## 8. Контракты компонентов

Собственные компоненты приложения (`app/components/*.vue`) — четыре штуки; остальное в `app/components/ui/` сгенерировано shadcn-vue и здесь не документируется.

Открытие диалогов реализовано через `v-model:open`, то есть пару `props.open` + `emit('update:open', value)`. Каждый диалог закрывает себя сам после успешной отправки; родитель получает только полезную нагрузку.

### 8.1. `ProjectDialog`

| Props | Тип | Описание |
| --- | --- | --- |
| `open` | `boolean` | видимость диалога |
| `project` | `Project \| null` (опц.) | заданное значение включает режим редактирования |

| Emits | Полезная нагрузка |
| --- | --- |
| `update:open` | `boolean` |
| `submit` | `{ name: string; description: string }` |

Поля формы инициализируются в `watch` на открытие (`open === true`) — из `project` либо пустыми значениями; ошибки при этом сбрасываются. При закрытии состояние не очищается, что безопасно: следующее открытие переинициализирует форму.

### 8.2. `TaskDialog`

| Props | Тип | Описание |
| --- | --- | --- |
| `open` | `boolean` | видимость диалога |
| `task` | `Task \| null` (опц.) | режим редактирования |
| `columns` | `Column[]` | варианты статуса |
| `defaultStatus` | `string` (опц.) | статус для новой задачи |

| Emits | Полезная нагрузка |
| --- | --- |
| `update:open` | `boolean` |
| `submit` | `{ title, description, priority, deadline, assignee, status }` |

Начальный статус выбирается по цепочке: `task.status` → `defaultStatus` → `columns[0].id` → `''`. Благодаря этому кнопка «+» в заголовке колонки создаёт задачу сразу в нужном статусе, а кнопка «Добавить задачу» в заголовке доски — в первой колонке.

### 8.3. `TaskCard`

| Props | Тип |
| --- | --- |
| `task` | `Task` |
| `columns` | `Column[]` |

| Emits | Полезная нагрузка |
| --- | --- |
| `edit` | `Task` |
| `remove` | `Task` |
| `move` | `(taskId: string, status: string)` |
| `dragstart` | `taskId: string` |
| `dragend` | — |

Просроченная задача получает класс `border-2 border-destructive`, бейдж срока — вариант `destructive`, и под карточкой появляется надпись «Задача просрочена». Атрибут `data-testid="task-card"`.

## 9. Валидация

Валидация выполняется в компонентах диалогов до отправки события `submit`; `useTracker` данные не проверяет. Сообщения выводятся под соответствующим полем классом `text-destructive`, отправка блокируется.

### 9.1. Проект (`ProjectDialog.submit`)

| Правило | Сообщение |
| --- | --- |
| Название непустое после `trim()` | «Укажите название проекта» |
| Название ≤ 100 символов | «Название не должно превышать 100 символов» |
| Описание ≤ 500 символов | «Описание не должно превышать 500 символов» |

Все три сообщения используют одну переменную `nameError` и выводятся под полем «Название» — в том числе ошибка длины описания. Проверки выполняются последовательно с ранним возвратом, поэтому одновременно видно не более одной ошибки.

### 9.2. Задача (`TaskDialog.validate`)

| Поле | Правило | Сообщение |
| --- | --- | --- |
| `title` | непустое после `trim()` | «Название задачи обязательно» |
| `title` | ≤ 100 символов | «Название не должно превышать 100 символов» |
| `status` | непустое | «Выберите статус задачи» |
| `description` | ≤ 1000 символов | «Описание не должно превышать 1000 символов» |
| `assignee` | ≤ 60 символов после `trim()` | «Имя исполнителя не должно превышать 60 символов» |
| `deadline` | если задан — разбирается как дата | «Некорректная дата» |

В отличие от диалога проекта, `validate()` собирает ошибки всех полей в объект `errors` и показывает их одновременно. Дедлайн в прошлом допустим — такая задача сразу помечается просроченной.

### 9.3. Колонка (`pages/projects/[id].vue`)

| Операция | Правило | Сообщение |
| --- | --- | --- |
| Добавление | название непустое после `trim()` | «Укажите название колонки» (в `columnError`) |
| Удаление | в проекте больше одной колонки | `toast.error('Нельзя удалить последнюю колонку')` |
| Переименование | проверок нет | — |

## 10. Оформление и темы

Единственный источник стилей — Tailwind CSS 4 и design-токены shadcn-vue в `app/assets/css/tailwind.css`; сторонних CSS-файлов, кроме `vue-sonner/style.css`, нет.

Тёмная тема включается модулем `@nuxtjs/color-mode`, который при `classSuffix: ''` ставит класс `dark` на корневой элемент. Переключатель — кнопка в шапке `layouts/default.vue`: `colorMode.preference` меняется между `light` и `dark`, иконка `Sun`/`Moon`, `aria-label` меняется вместе с состоянием. Выбор сохраняется в `tracker-theme`.

Утилита `cn(...inputs)` из `app/lib/utils.ts` объединяет классы через `clsx` и разрешает конфликты Tailwind через `twMerge`. Используется во всех UI-компонентах при слиянии базовых классов с переданными через `props.class`.

Контейнер уведомлений `Toaster` (`vue-sonner`) размещён в макете один раз, позиция `bottom-right`; вызовы `toast.*` доступны из любого места приложения.

Сетки адаптированы от 768 px (`md:`) и шире — см. [Ограничения](/guide/limitations), п. 8.

## 11. Точки расширения

**Новая операция над данными.** Добавьте функцию в `useTracker`, вызовите в ней `save()` и включите имя в возвращаемый объект — состояние через `useState` уже разделяется всеми компонентами.

**Новое поле задачи.** Потребуются согласованные изменения в `app/types/index.ts`, полезной нагрузке `createTask`/`updateTask`, форме `TaskDialog` (поле, инициализация в `watch`, правило в `validate`), отображении `TaskCard` и, при необходимости, в конвейере `filteredTasks`. Миграции для данных, уже лежащих в `localStorage`, не предусмотрены: старые записи просто не будут содержать нового поля, поэтому его чтение должно быть устойчиво к `undefined`.

**Новый фильтр доски.** Добавьте `ref` в `pages/projects/[id].vue`, шаг в `filteredTasks`, элемент управления в панель фильтров и сброс в `resetFilters()`.

**Экспорт и импорт данных.** Формат уже описан: содержимое ключа `tracker-data` — это `{ projects, tasks }`, то есть `TrackerState`. Достаточно сериализовать `projects.value`/`tasks.value` в файл и при импорте присвоить их обратно с последующим `save()`.

## 12. Особенности реализации, важные при доработке и тестировании

1. **Мутации массивов на месте.** `updateProject`, `renameColumn`, `updateTask`, `moveTask` и `setProjectArchived` изменяют объекты, полученные поиском, а `deleteProject`/`deleteTask` заменяют массив результатом `filter`. Оба подхода корректны для реактивности Vue 3, но объекты, возвращённые из `getProject`/`getProjectTasks`, разделяют ссылки с состоянием — изменение такого объекта в компоненте изменит состояние без вызова `save()`.
2. **Значения `order` могут дублироваться.** И `createTask`, и `moveTask` вычисляют `order` как число задач в целевой колонке. После удаления задачи из середины колонки следующая новая задача получит уже существующее значение, и порядок внутри колонки при сортировке «по порядку добавления» станет неопределённым для таких задач. Перетаскивание не меняет порядок внутри колонки — только статус.
3. **Сохранение при каждом нажатии клавиши** в диалоге колонок (см. 7.2) — самая частая операция записи в `localStorage` в приложении.
4. **Пустое название колонки допустимо** при переименовании: проверка есть только при добавлении.
5. **`load()` вызывается ровно один раз за жизнь страницы.** Изменения в `localStorage`, сделанные другой вкладкой, не подхватываются: обработчика события `storage` нет, и сохранившая последней вкладка перезаписывает состояние.
6. **Тестовые атрибуты.** Для автоматизации уже расставлены `data-testid`: `add-project` (`pages/index.vue`), `add-task` (`pages/projects/[id].vue`), `task-card` (`TaskCard.vue`). Прочие элементы адресуются по доступному имени — у кнопок-иконок заданы осмысленные `aria-label` («Действия с проектом», «Действия с задачей», «Добавить задачу в колонку», «Удалить колонку», «Удалить проект», «Включить светлую/тёмную тему»), а поля формы связаны с `Label` через `for`/`id`.
7. **Подготовка состояния в тестах** выполняется записью в `localStorage` по ключу `tracker-data` **до** загрузки страницы: `load()` срабатывает в `onMounted` корневого компонента и читает хранилище единожды.
8. **Проверка просрочки зависит от системной даты** браузера, в котором выполняется тест: `isOverdue` сравнивает срок с текущей датой, приведённой к началу суток.
